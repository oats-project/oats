# OATS 0.69.19

The official catalog pins oats.aweb 1.42.1, which makes retained seats safer
and shortens the always-loaded messaging instructions, and oats.framework
1.25.2. Instances in `workspace` and `directory` mode can make extra trees of
their own for repository work. `oats host run` runs the resume sweep each
minute, and the sweep retries a refused start and counts a home's starts per
hour. The Desktop's sidebar lists instances newest first. oats.okf stays
6.0.3.

## Upgrade

- **Either order of the Desktop and the CLI works** from a Desktop newer than
  0.69.17 ([Either order works](../upgrading.md#either-order-works)). A
  Desktop of 0.69.17 or older still goes first.
- **Package pins:** oats.aweb 1.42.1 (from 1.41.0) and oats.framework 1.25.2
  (from 1.25.0). oats.okf stays 6.0.3. `oats sync` takes them; the two oats.aweb
  steps below apply only where they match.
- **A retained seat reads its aweb service only from its own record.** If
  you set `OATS_AWEB_URL` for a retained seat, record the server in the seat
  with `aw workspace connect --service <server>`, run in the seat's parent
  directory, then unset the variable. A seat whose `workspace.yaml` already
  names its server is unchanged.
- **A non-boolean `identity.e2ee` or `identity.takeOver` is refused** at spawn
  and start. `true`, `false` and the strings `"true"`/`"false"` are accepted,
  and an empty value reads as unset. Set any other value to `true` or `false`.
- **Scripts that read `oats session resume --json`:** the row reason
  `refused-this-boot` is gone. A refused start waiting for its next attempt
  is `start-refused-retrying`, and `keeps-getting-lost` now means 3 starts in
  the last hour (details under Changed). The Desktop doesn't depend on these
  reasons.
- **Respawn instances** to take the shorter aweb text and the extra-trees
  briefing of the `workspace` and `directory` modes: a running instance keeps
  the text it was composed with.

## Added

- **Team image acceptance in CI.** Pull requests now build the team agent image
  from their exact head commit and run the existing container acceptance script
  on an amd64 runner with a private Compose fixture and no inference credentials.
  Release image publication is prepared after the OATS release, by digest with an
  exact release retention tag. The run and release notes record the immutable
  reference. Publication remains disabled pending the registry decision and
  requires a stable OATS release tag of at least 0.69.18 plus a committed final
  aw image pin of at least 1.36.59.

- Manual verification of an image built with its selected commit's own packed
  kernel, with exact installed-file paths, sizes, modes and hashes checked
  against HEAD. A separate proof compares the default installed payload with
  and without the read-only build-context mount. Packed mode remains manual
  until the compatible image baseline lands; publication stays disabled.
  With the committed baseline, the packed job refuses; positive real
  packed-image acceptance is **NOT RUN** until that compatible baseline lands.

## Changed

- **The catalog pins oats.aweb 1.42.1** (from 1.41.0). 1.42.0 is never
  pinned: a comment in it named the kernel's private module, which the mirror
  check refuses. 1.42.1 requires OATS >=0.68.0, the aw floor stays 1.36.33,
  and the tested aw is 1.36.58. Most of
  the release is about retained seats: an atomic seat lock, a lock held on
  another host refuses with its release, a killed or failed spawn never
  deletes the standing identity's workspace, and a seat with no membership of
  its team is refused before any effect. The captured-execution variables are
  now ignored, with one warning each. The always-loaded messaging
  instructions are shorter, and new spawns get the new text.

- **The Desktop's Add machine dialog gives an invented host as its example.**
  The host field's placeholder now reads "ssh host alias, e.g. devbox"; it
  named one deployment's own machine. Nothing else in the dialog changes.

- **The `directory` work mode teaches extra trees.** Its briefing granted
  none, while the instance-boundary block says repository work happens "there,
  or in the extra trees your mode block grants", and `oats worktree add`
  already worked from a directory home. `./work` stays an owned directory
  that never becomes a repository; repository work that needs a branch goes in
  an extra tree of the instance's own, with the same "Extra trees" section as
  the `workspace` briefing:
  `oats worktree add --purpose <p> --branch <b> --base <remote-branch> --repo <repo>`.
  `--repo` is always named: the home's recorded repository is configuration
  context, the deployment directory by default, so `add` without it is
  refused there (`E_CLONE_MISSING`). A directory instance's `TASK.md` says the
  same ("Work in ./work; do repository work only in your extra trees.")
  ([work modes](../souls-and-instances.md#directory--independent-execution)).
  Existing homes keep the briefing they were composed with; a new spawn picks
  this one up.

- **`oats.framework` 1.25.2: `oats.core` 2.13.2** (through 1.25.1).
  `oats.core`'s `/oats-operate` says that `workspace`- and `directory`-mode
  instances can make extra trees too: work that needs a branch goes in an
  extra tree of the instance's own, made with `oats worktree add --repo
  <repo>`. Member clones stay read-only, and a directory instance's `./work`
  never becomes a repository.

  No capability needs a newer OATS: `oats worktree add --repo` has worked
  from those homes since OATS 0.49.0.

- **`oats host run` runs the resume sweep each minute, not only at its
  start.** An agent whose session is lost while the host runs (its harness
  crashed or was killed) is started again by the sweep of the next minute,
  within the sweep's own bounds: at most 3 starts of a home in an hour, a
  refused start retried with backoff, and a home given up after 3 such hours
  in a row. Before, a container that stayed up never started a lost agent
  again; only a restart of the container did.

  A home the sweep started counts as seen running for that start. A home
  that is lost again within the minute, before any read saw it running, is
  therefore started again and counted, not left as `not-seen-recently`.

  The sweep replaces the listing `oats host run` ran each minute, and records
  what that listing recorded. A sweep that still runs at the next minute is
  not run beside itself. Progress says a sweep only when its outcomes differ
  from those of the sweep before. The answer's `sweep` is the first sweep's.
  Stopping is unchanged: a sweep that runs gets the same 10 seconds, and the
  admission fence stops its further starts.

- **`oats session resume` tries a refused start again, and counts a home's
  starts per hour.** A start the sweep ran and that was refused (a launch
  variable not set, no wake broker running yet) launched nothing and says how
  the host was at that moment. It no longer answers the loss for good: the
  sweep tries that home again no sooner than 1 minute later, doubling to 15
  minutes at most, until the loss is 24 hours old. A home that keeps getting
  lost is still started at most 3 times, now in an hour instead of in a boot,
  and a sweep starts it again when the oldest of those starts is an hour old.
  A home that uses up its starts 3 hours in a row is given up until a person
  starts it.
  Both the count and the delays are kept for one boot. On upgrade, a home's
  count of starts for the current boot begins at zero once: the earlier
  kernel's note holds no start times.

  **Contract change for clients of `oats session resume --json`**
  ([the machine sweep](../desktop-cli-api.md#the-machine-sweep-oats-session-resume)):
  - the row reason `refused-this-boot` is no longer emitted. A refusal that
    is waiting for its next attempt is `start-refused-retrying`, with the
    refusal's `code` and `message`;
  - `start-refused`, `start-refused-retrying` and `keeps-getting-lost` rows
    carry `nextAttemptAt`, an ISO time (not on a host without a boot id,
    where nothing is noted);
  - `keeps-getting-lost` keeps its name and now means 3 starts in the last
    hour, not in this boot. It is final only without `nextAttemptAt`: after
    3 such hours in a row;
  - a refused start and `keeps-getting-lost` no longer make later sweeps
    answer the home `not-seen-recently`.

- **The Desktop's sidebar lists instances newest first.** The instance tree
  is in spawn order, newest on top, instead of by name, at every level: a
  group of related instances by its first instance, the children under a
  parent the same way. Spawning a child doesn't move its group, and starting
  or stopping an instance still moves nothing. The TUI's list and the command
  palette's never-focused rows follow the same order.

- Release image preparation installs the exact kernel version just published,
  preserves unrelated committed lock entries and retains the generated inputs.
  Acceptance verifies the installed version before registry login. Publication
  remains disabled; its prepared path adds only the exact release retention tag,
  refuses tag conflicts and records an immutable digest receipt with explicit
  build/startup coverage and unrun agent and containment checks.

- **The `workspace` work mode teaches extra trees.** Its briefing no longer
  lists worktrees among the Git operations it forbids, which contradicted the
  instance-boundary block ("repository work happens there, or in the extra
  trees your mode block grants"). Member clones stay read-only through
  `./work`; work that needs a member's branch goes in an extra tree of the
  instance's own, made with
  `oats worktree add --purpose <p> --branch <b> --base <remote-branch> --repo <member>`,
  which moves none of the clone's refs. `--repo` is always named in this mode:
  the home's recorded repository is the deployment directory, so `add` without
  it is refused (`E_CLONE_MISSING`). A workspace instance's `TASK.md` says the
  same. What work an instance takes on stays its role's and its task's call
  ([work modes](../souls-and-instances.md#workspace--cross-repo-coordinator)).
  Existing homes keep the briefing they were composed with; a new spawn picks
  this one up.
