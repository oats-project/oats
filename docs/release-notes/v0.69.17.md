# OATS 0.69.17

0.69.17 moves OATS's two coordination souls, `oats-engineering-expert` and
`oats-product-expert`, onto knowledge subjects (`okf.json` version 2). The
official catalog pins oats.okf 6.0.2 and oats.framework 1.24.1; oats.aweb
stays at 1.39.0.

## Upgrade

- **Either order of the Desktop and the CLI works.**
  [Upgrading](../upgrading.md) installs the Desktop first, and a host that
  installed the CLI first is fine too: the 0.69.17 Desktop accepts OATS CLIs
  `>=0.26.0 <0.70.0`, as the 0.69.16 Desktop does.
- **Package pins:** oats.okf 6.0.2 (from 6.0.1) and oats.framework 1.24.1
  (from 1.24.0). Neither asks for a hand step: `oats sync` takes them. A
  deployment that keeps its own pins changes nothing until it moves them.
- **Respawn an instance of `oats-engineering-expert` or `oats-product-expert`
  once** after `oats sync`. An instance keeps the `okf.json` its spawn
  recorded, so one started before this release still reads and proposes to
  its old node; a new spawn reads the soul's subjects. The soul needs a
  knowledge base bound with the subject layout: on a base that is not
  bridged, its spawn refuses with `E_CONFIG` naming the base
  ([okf.json version 2](../knowledge.md#the-souls-okfjson)).

## Changed

- **`oats.framework` 1.24.1: `oats.setup` 2.15.1's `/oats-onboarding` names
  `oats.okf` 6.0.2**, the release the catalog pins, in its knowledge card and
  its workspace example. Nothing else changes, and no capability needs a
  newer OATS.

- **The official catalog pins oats.okf 6.0.2** (from 6.0.1), and OATS's own
  workspace takes it. A claim merged into a bridged base without the
  maintainer's id stamp no longer stops version-2 spawns: readers warn
  `W_ID_MISSING`, `oats okf bases` shows it, and writers and strict checks
  still refuse. The generated mirror under `mirrors/oats-okf*` is finalized
  from the v6.0.2 tag
  ([oats.okf's CHANGELOG](https://github.com/oats-project/oats-okf/blob/v6.0.2/CHANGELOG.md)).

- **`oats-engineering-expert` and `oats-product-expert` read by subject**
  (`okf.json` version 2). The engineering expert's subjects are
  `system/oats-kernel`, `system/oats-desktop`,
  `workstream/provider-integration`, `workstream/operations` and
  `workstream/coordination`; the product expert's are
  `workstream/oats-direction` and `workstream/positioning`. Their spawn brief
  lists those subjects, and their texts say each proposed claim names the
  subjects it is about. Every other soul keeps its version-1 `okf.json`.
- **`oats.workspace-experts` 1.3.1:** its table of surfaces names, beside each
  knowledge node, the subject that absorbs it ("Knowledge it reads").
