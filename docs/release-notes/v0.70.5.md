# OATS 0.70.5

Unreleased

A patch release: OATS reports a harness running in a session-provider home
it stopped, tells the provider which stop is the host's, and adopts a home
stopped with the host whose harness runs again. The Desktop's main screen
takes the redesign's look.

## Upgrade

- **The Desktop and the CLI** can be upgraded in either order.
- **The pi bridge** (`@awebai/oats-pi` 0.70.5) reaches each pi folder with
  `oats update`.
- **A session provider's author:** `inspectMany` now also receives the
  homes OATS stopped, with the endpoint of their last session. Answer each
  one by itself, by what is there (`running: true` only for a harness that
  runs), and never fail the whole call for one of them. A `stop` may carry
  `reason: "host"`: never refuse a stop with or without it
  ([capabilities.md](../capabilities.md#stop)). The wire version is
  unchanged.

## Added

- **OATS reports a harness that runs in a provider home an operator stopped**
  (feature `provider-outside-oats`). A session provider's own product can
  start a stopped session's harness again without OATS, for example when a
  person types a message there. `oats status` now asks the provider about
  its stopped homes in the `inspectMany` call it already makes for the
  running ones of their group (one call for the provider where none of its
  homes runs, after every running home was asked), and the row of a home
  whose provider answers a live harness carries `outsideOats: {code:
  "running-outside-oats", backend, message}` in `--json`, and the message on
  a line under the row in text; `oats server roster` relays it in that exact
  shape. The key is a report and nothing else: the row stays `running:
  false`, `runtimeState: "stopped"`, an input to the home stays refused, the
  sweep never resumes an operator's stop, and the read writes nothing. A
  provider that fails or does not answer leaves the row stopped, without the
  key. The message names the remedy: `oats instance stop <name>`, or a start
  from OATS ([desktop-cli-api.md](../desktop-cli-api.md#row-outside-oats)).
- **A session provider is told which stop the host's shutdown is.** The
  `stop` input of `oats host run`'s shutdown carries `reason: "host"`, as
  do the stops that follow a failed resume notice of such a home and an
  input that crossed that stop, and no other stop carries a `reason`, so a provider that archives what it stops
  can keep that session for the resume's input. The key is optional and the
  wire version is unchanged ([capabilities.md](../capabilities.md#stop)).

## Changed

- **The Desktop's main screen now looks like the redesign's prototype**
  (the Desktop UI rework, slice 3d). This changes the look only: no key, no
  action and no contract changes. On an Omarchy computer the default colours
  are still Omarchy's own.
  - **The sidebar:**
    - **WORKSPACES** and **AGENTS** are small capitals headings, and the
      sidebar sits a shade darker than the main area in the Dark theme;
    - each agent is two compact lines: its name, then its harness's mark
      (Claude, Codex or Pi, small and in a light grey) and its soul, smaller and muted. The
      machine shows only for an agent on another machine
      ("reviewer · build-host"). This computer's name shows once, at the
      right of the status line;
    - **+ New agent** is at the end of the list of agents. Its key and its
      palette entry are unchanged;
    - "new" is a small pill;
    - **Automations** says "1 failed" in red after its name while a
      schedule's last run failed, instead of a red dot.
  - **Tabs** are small pills, 28px tall in a 44px bar: the number, the name,
    then the status dot. The active one is filled and its number is in the
    accent colour. A tab's × shows on the active tab, a hovered tab and a
    focused tab; Delete and Alt+W still close any tab.
  - **The agent view:**
    - each fact is a strip of its own, with its time at the right;
    - the question is a card: "needs you" and its keys on top
      ("1–2 choose · Enter sends · c context · Esc terminal"), the question,
      then its options as boxed rows, each with its number;
    - in the Dark theme, the terminal sits on the app's own background. Two
      colours were adjusted slightly to keep their contrast: ANSI black and
      the selection. The terminal's text size and spacing are unchanged.
  - **The status line** at the bottom is a quieter 28px key bar: the keys in
    the window's own type, with a small dot between two.
  - **The sheets** (Appearance, Keyboard shortcuts, an agent's mail, the
    leader's help sheet) have the prototype's titles, small uppercase section
    headings and spacing.

- **A provider home stopped with the host whose harness runs again is
  adopted, not resumed.** When a person's message reached its session before
  the sweep, or the harness came back, `oats status` reads the home running
  from the provider's answer, and the sweep clears the stop without sending
  its resume notice into the running harness; nothing is counted, and the
  sweep's row is `already-running`. `oats session start --resume` of such a
  home does the same and answers `E_SESSION_RUNNING`. The resume of a home
  stopped with the host now asks the provider's `inspect` before its notice.
  Until a sweep has adopted such a home its row reads running while its
  input is still refused, and the row is no longer `lost`, so a client that
  starts a sweep when it sees a lost home does not start one for it: `oats
  host run`'s sweep, each minute, adopts it.
- **An ordinary `oats session start` or restart of a provider home stopped
  with the host records that stop as an operator's first.** Its stop of the
  old session carries no `reason`, and a launch that fails leaves the home
  `stopped`, not `lost`: no sweep resumes it through a session that stop
  ended.
- **`oats instance upgrade` refuses a provider home recorded stopped whose
  harness runs** (`E_SESSION_RUNNING`, naming `oats instance stop <name>`),
  at the plan and at the apply: it asks the provider once, and never upgrades
  under a running harness. An upgrade whose provider cannot be asked goes on,
  since the home is as OATS recorded it.
- **A session provider's `inspectMany` now receives the homes OATS stopped**,
  with the endpoint of their last session, beside the running ones. `oats
  status` still never calls `inspect` for a stopped home, and never reads a
  home an operator stopped as running
  ([capabilities.md](../capabilities.md#inspect-and-inspectmany)).
