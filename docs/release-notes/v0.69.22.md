# OATS 0.69.22

The Desktop's UI rework continues: Home is where a window opens; Souls, a soul's page, Capabilities, Teams,
Machines and Setup are calm rows; the command palette is the one place to reach everything, with a status line
and centred sheets; and the sidebar's chevron and count now come after an agent's name. The Desktop's default
leader is Ctrl+Space. Instances can be pinned from the Desktop and the Terminal UI. The catalog pins oats.aweb
1.45.0. A team container can take read-only inputs and a setgid outbox, and can run an opt-in, experimental bb
server. The getting-started skill sets up a person's own aweb server on a private AWID registry too.

## Upgrade

- **Either order of the Desktop and the CLI works** from a Desktop newer than
  0.69.17 ([Either order works](../upgrading.md#either-order-works)). A
  Desktop of 0.69.17 or older still goes first.
- **Package pin:** oats.aweb 1.45.0 (from 1.43.0, through 1.44.0).
  oats.framework stays 1.26.0 and oats.okf 6.2.0. `oats sync` takes it.
  Respawn instances, or move a stopped one with `oats instance upgrade`, to
  take the new module.
- **oats.aweb 1.44.0's setup changes** (under Changed): `setup --install-aw`
  installs the tested aw by default; bare API-key setup refuses before
  `aw init` in another team's root; `setup --create` and tokenless
  `setup --join` check only their own selected root.
- **The Desktop's leader is Ctrl+Space by default.** A leader you set is
  kept, and Ctrl+X is one click away on the Keyboard shortcuts sheet. Where
  an input method takes Ctrl+Space (macOS with two input sources or more,
  IBus, Windows CJK IMEs), choose Ctrl+X there. The Terminal UI keeps Ctrl+X.
- **`oats tui`: `p` is a new default key (pin).** A `tui.json` that binds `p`
  to another action is refused at the start, with a line that names the key
  and both actions. A tui.json that binds p to another action must move that
  action, or bind `pin` to another key (or to none, `"pin": []`). See
  [Pinning](../tui.md#pinning).

## Added

- **A team container can run a bb server.** Opt-in: build the derived image
  `container/agent-bb` on a team image, select it with `AGENT_IMAGE` and
  include `container/agent/compose.agent.bb.yaml`. The supervisor then starts
  one [bb](https://github.com/get-bb/bb) server on the container's loopback,
  after the wake broker and before sshd and `oats host run`, restarts it if
  it ends, and stops it after host run has stopped the agents. The service
  still publishes no port; the operator reaches bb over the SSH route with
  `container/agent-bb/relay.mjs`. A container that does not opt in runs as
  before, and the team image holds no bb. The server is unused until agents
  are spawned with the bb session provider, which arrives with a later
  kernel. This is experimental: the bb image, `compose.agent.bb.yaml` and
  the relay will move to the bb package repository once it exists, with no
  compatibility promise on those paths, on `AGENT_BB` or on the image's
  recipe, so that move will not be a breaking change. See
  [A bb server for the team](../container.md#a-bb-server-for-the-team).

- Team-agent containers can mount one operator-provisioned input directory
  read-only at `/inputs`, using `TEAM_INPUT_DIR` and the optional
  `compose.agent.inputs.yaml` fragment. Acceptance checks the running mount,
  readability and write refusal; CI also checks the base has no input folder
  and missing sources fail without host-path creation. An optional
  `compose.agent.outbox.yaml` fragment adds a writable export queue with a
  dedicated supplementary group and setgid ownership. Acceptance checks group
  inheritance and private state. Every agent can read the inputs and read/write
  the queue; the publisher, its ledger and credentials stay outside OATS. See [agent team container](../container.md).

- **Home in the Desktop.** A workspace now opens on Home, the first pinned row in the sidebar, which answers what needs you and what you have on one page:
  - **The board.** Agents that need you, each with its message, then the running ones, newest first. A group with nobody in it isn't shown, and stopped agents aren't listed.
  - **The overview.** Agents, Souls, Capabilities, Teams, Machines and Graph, each saying how many you have. Enter opens that part of the Workspace page, and Esc comes back to Home.
  - **Home › Agents.** Every agent, running or stopped, with its soul, machine and state, and who started it.
  - **A new workspace** shows what OATS does in two lines and three keys.

  The palette's **Home** (among its sections) opens Home; it has no key of its own yet. The roster's order doesn't change: urgency is sorted on Home only.

- **Pinned instances in the Desktop and the TUI** (feature `instance-pin`).
  A pinned instance is listed at the top of its machine's list, in the
  Desktop's sidebar, the TUI's list and the command palettes' rows you have
  not focused. Pinned instances come first at every level of the tree. An
  instance counts as pinned when it or one below it is, so pinning a child
  lifts its whole group and the path down to it. Among pinned instances the
  order is spawn time, newest first, as for the rest.
  - The Desktop: a row's context menu offers **Pin to top**, or **Unpin** on
    a pinned instance, and the command palette offers **Agent: Pin to
    top** / **Agent: Unpin** for the instance the leader keys act on. A
    pinned row shows a pin after its name, which a screen reader hears as
    "Pinned". A group that holds a pinned instance, its top instance
    included, doesn't start collapsed, so the pin is seen with its group;
    closed by hand, it stays closed.
  - The TUI: `p` pins or unpins the selected instance at once, and the line
    under the sidebar's title says what it did, or why it did nothing.
  - Both run `oats instance pin <name> on|off`. The pin is the instance's
    home's, so everyone who views that machine sees the same pins. Without
    `instance-pin` on this computer, or on an instance's server, the order
    and the menus stay as they were.

  See [Pinned instances](../desktop.md#pinned-instances) and
  [Pinning](../tui.md#pinning).

## Changed

- **The getting-started skill sets up a workspace on the person's own aweb
  server on a private AWID registry too** (#1966). Step 1 no longer stops
  there: it asks the registry's origin, and tells the person that their
  namespace's `_awid` DNS record must name that registry
  (`aw id namespace prepare-controller --domain <domain> --registry <origin>`
  makes one that does). Step 9 records it first, before any other
  `oats aweb` command, with `oats aweb setup --soul <soul> --registry
  <origin>`, the host setting `settings.oats.aweb.registry` that admits a
  private registry. The skill still never sets `AWID_REGISTRY_URL`. That
  branch needs oats.aweb 1.43.0 or later, the first release with
  `--registry`; the public registry keeps 1.42.1. On a private registry,
  when the setup expert needs the host wake broker, the skill first checks
  the install read-only (`oats aweb wake install --plan`) and goes on only
  when it passes, since
  `oats aweb wake status` can't tell which registry a running broker
  serves. On any refusal it stops and leaves the fix to the person: for
  example a broker for another registry (`E_WAKE_REGISTRY_CONFLICT`), or
  one started by hand (`E_WAKE_RUNNING_UNSUPERVISED`). On a machine with
  no service manager, where a plain `aw wake run` would not carry the
  registry, it offers a Claude or pi setup expert instead.

- **OATS pins oats.aweb 1.44.0** (from 1.43.0). Floors are unchanged: OATS >=0.68.0, aw >=1.36.33, tested aw 1.36.58. What a deployment must change:
  - **`oats aweb setup --install-aw` installs the tested aw (1.36.58) by default,** where it installed the newest aw 1.x. Pass `--aw-version <v>` to keep another.
  - **Bare API-key setup refuses before `aw init`** in an existing root that belongs to another team, or that lists memberships while no team is configured. Point `settings.oats.aweb.roots[<team>]` at the intended team's root, or at a fresh `.aweb-roots/<label>` directory, or configure the team first, then retry. A root with confirmed empty membership still bootstraps.
  - **`oats aweb setup --create` and `setup --join` without a token check only their own selected root.** An unreadable default root no longer blocks them, which reverses 1.43.0's interim refusal. They now refuse when their selected root's membership is unreadable or belongs to another team. Invited `setup --join` still reads the default root.

  Setup also names the source of the root it uses. Registry admission stays explicit through command formatting and retire cleanup. aw JSON answers with trailing stdout text are refused. Running instances keep the module they were spawned with: respawn them, or move a stopped one with `oats instance upgrade`, to take 1.44.0.

- **OATS pins oats.aweb 1.45.0** (from 1.44.0). Floors are unchanged: OATS >=0.68.0, aw >=1.36.33, tested aw 1.36.58. A launch on a session provider (an `OATS_BACKEND` other than `tmux` or unset) is delivered by the host wake broker, whatever `delivery` and the runtime say. It is inert until the kernel launches homes on a session provider. Homes on tmux behave as before, and nothing changes for them. A host that runs a session provider's homes under `delivery: channel` keeps `aweb-channel` at 1.7.9 or later and `@awebai/pi` at 0.3.10 or later. Running instances keep the module they were spawned with: respawn them, or move a stopped one with `oats instance upgrade`, to take 1.45.0.

- **A team container's bb server refuses a damaged token file.** With the bb
  fragment, a `claude-token` file whose token has whitespace inside it (a
  space, a tab, a line break) now fails the container start, before any child, with one line
  naming the file's rule. Before, bb started and reported ready while every
  model call failed. The docs also say to spawn bb agents with `--yolo` in a
  team container, where bb's sandboxed modes cannot start. See
  [A bb server for the team](../container.md#a-bb-server-for-the-team).

- **Desktop: the workspace's catalogue pages read as calm rows** (the Desktop UI rework, slice 3b).
  - **Capabilities** is one list. Core capabilities (knowledge, messaging, tasks) come first with a
    dim **core** tag, then the rest by name. Each row has the capability's name and who made it: a
    ✓ for an official one ("Official: in the OATS catalog" for a package pinned from the catalog,
    "Official: from the OATS repository" for a capability of the OATS repository), else **by** its
    source. The mark is the Desktop's rule over workspace status, not a trust claim (a kernel fact
    is [#1981](https://github.com/oats-project/oats/issues/1981)). It also has one line of what it does, and a
    **default** tag on the workspace's defaults. One sentence above the list says what defaults are
    for. The sections, repository pills, colour tiles and two-letter marks are gone. A package's
    name and version are in Setup's Packages box.
  - **A soul's page** lists its capabilities with the same row: the same mark or **by** its source
    (the workspace's own repository is named too), core first, and no **default** tag.
  - **A capability's page** reads top to bottom: what it does, then its **Skills**. Enter on a
    skill opens the whole skill in the pane, and Esc returns. Commands, Settings, Triggers, Hooks,
    Used by, Comes from and Files are folded underneath. Nothing the page showed before is gone.
  - **Teams** names its two sections **Workspace teams** and **This computer's teams** (the teams
    in this computer's `oats-local.yaml`). Each says what it holds in one sentence, and its lists
    count your agents.
  - **Machines** opens on the list of the computers the workspace runs on. Each row says whether
    the computer is reachable and its OATS version. Enter opens
    a machine, with Check and Remove. Its **Map** is the earlier Machines view.
  - **Setup** is its list only; its graph is gone. A member's **Details** (or **Why?**) opens its
    membership under its row.
  - **Connections** says what the GitHub connection is for.

- **The sidebar's chevron comes after the name.** An agent with agents under it shows its chevron and their count right after its name, not before it, so every name at a level starts at the same place. A click on the chevron still opens or closes the group, and a click anywhere else on the row still opens its terminal.

- **The sidebar's roster heading reads "Agents"**, and the Workspace page no longer has a pinned row of its own: Home opens it, and Home's row stays selected while it shows. ⌘2 / Ctrl+2 and **View: Workspace overview** still open it.
- **A live agent is "running" on Home.** OATS doesn't report working or idle yet, and the Desktop doesn't guess. There is no "New" group for agents that stopped since you last looked either, because nothing records that yet.

- The command palette is the one place to reach everything: the agents that need you, your recent agents, the sections, the commands, and a **New agent: <soul>** row per soul. Quick Open's separate overlay is gone: ⌘P / Alt+P opens the palette on its souls (`+`).
- A status line along the bottom of the window shows the three most useful keys for where you are, says why a key could not act, and says what was just done. Stop, Start and Restart keep their dialogs.
- Stop and Retire are centred sheets; after a retire, a dim ✕ row stays where the agent was for ten seconds.
- Pressing the leader shows a small help sheet with the keys it takes; the leader then `?` pins it until Esc, and the Keyboard shortcuts sheet can turn it off.
- **Appearance** is one sheet for the theme (System, Dark, Light, more), the terminals' font and their size. **Choose…** sets a terminal font family by name in the sheet; the palette's **Terminal: set font family…**, which did nothing in the Desktop before (it used a prompt Electron doesn't support), opens that field, and choosing a named font clears a family chosen by name, which used to win over it. The window's text is always the system font: Omarchy's font now applies to the terminals only. "White" is now Light and "This computer" is System, with the same behaviour.
- The keyboard shortcuts editor is a sheet, with a **Leader** choice and the help sheet's setting at its top.
- **Keys:** the leader is now **Ctrl+Space** in the Desktop (Ctrl+X stays one click away on the Keyboard shortcuts sheet; a leader you set yourself is kept). Pressed twice it sends Ctrl+Space (NUL) to the program in a terminal. If your input method takes Ctrl+Space (fcitx or IBus with two input methods, macOS input sources), choose Ctrl+X. New: **Alt+N** opens New agent; the leader then **h** / **v** split right / down and **b** hides or shows the sidebar (also in `oats tui`, where `b` hides or gives back the list); **Delete** on a roster row retires (the sheet), beside `D`. Every other key is unchanged; the TUI's leader stays Ctrl+X for now.
- Status-line messages also say when the terminal in front loses its server and when it is back (the pane's countdown and **Reconnect now** are unchanged).

- **Desktop: Souls, and a soul's page, read calmly** (the Desktop UI rework, slice 3a).
  - **Workspace › Souls** groups souls by where they come from (the workspace's
    repository first, then its other members, then each package) and lists each
    group in kind order: maintainers, experts, developers, operations, then the
    rest. The kind is read from the soul's name (`-maintainer`, `-expert`,
    `-developer`; a `setup`, `operator`, `admin` or `ops` word is operations):
    OATS reports no role of its own yet.
  - A card shows what the soul does, how many of its agents run and its kind.
    **v** (or **Grid** | **Table**) shows the same souls as a table: name, what
    it does, kind, agents running, harness · model, and whether it is ready
    here. Each window remembers its choice.
  - The card's **Spawn** button, **Group by Team** and **About souls** are gone.
    Start a new agent of a soul from its page (**New agent**), Quick Open or the
    palette.
  - A soul's page is one column: its harness and model, its teams (the editable
    list on this computer folds out under them), its knowledge, and **Ready**,
    or the one thing that stops a spawn here, with the detail and the soul's
    readiness checks under **Details**. Then its capabilities as one list of
    rows, core ones first with a dim **core** tag, each with where it comes from
    and one line of what it does. Then its two prompts as two tabs, **Soul
    instructions** and **Composed instructions**, each with its sections listed
    beside it, and its skills folded under **Skills**. The page no longer lists
    the soul's agents: the Souls grid and table count them.

- The kernel test runner fails when a `real aw` regression skips, naming the
  missing coverage. Three normally skipped provider-owned opt-ins were
  removed; container auth checks now execute acceptance orchestration against
  a strict subprocess boundary. [Test ownership](../design/2026-11-18-kernel-test-ownership.md)
  records the source checks removed or replaced and the documented guidance
  checks retained.

## Fixed

- Every official package mirror is now generated from its catalog-pinned Git
  tag and checked for complete file sets, bytes, executable modes and symlink
  targets in pull-request CI. Workspace and current documentation/skill pins
  are checked against the catalog; the packed-artifact smoke reads its pins
  from the same source. See [the mirror procedure](../official-catalog.md#updating-the-test-mirrors).

  pinning oats.aweb 1.44.0, which includes the transferred provider regressions.
  Keep hook-1-12-1 until its current token-hygiene menu assertions have released

  lists every disposition and this hold. The kernel retire-hook contract test
  is unchanged, and a focused test preserves the real mirror answer's coupling
  to the kernel cleanup classifier.
