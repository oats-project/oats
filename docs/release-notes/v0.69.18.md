# OATS 0.69.18

From this Desktop on, the Desktop and the CLI can be upgraded in either order:
a Desktop accepts a newer CLI and holds back only what it was not tested with.
The Desktop's backend now listens on a private socket and checks a per-launch
credential on every request. Instances are named for their role in the
coordination (`<descriptive>-<role>`), in the kernel's suggestion, the
Desktop's spawn dialog and oats.core alike. The team container supervises its
wake broker. The official catalog pins oats.aweb 1.41.0, oats.okf 6.0.3 and
oats.framework 1.25.0.

## Upgrade

- **From this Desktop on, the Desktop and the CLI can be upgraded in either
  order.** A Desktop newer than 0.69.17 accepts an OATS CLI of a later minor
  or major version and holds back what it was not tested with until it is
  updated. A Desktop of 0.69.17 or older still refuses such a CLI: where one
  is installed, install the new Desktop first
  ([Either order works](../upgrading.md#either-order-works)).

- **Start the wake broker before a broker-delivered home's next start.**
  From oats.aweb 1.40.0, `oats spawn` and every start of a home the host
  wake broker delivers to (Codex, `delivery: session`, or a runtime with no
  aweb channel of its own) refuse while no broker runs, with
  `wake-daemon-not-running`. The message names the start for the host:
  `oats aweb wake install` in your own terminal, or `aw wake run` as a
  supervised process where there is no service manager. Check with
  `oats aweb wake status`. Claude and pi homes under channel delivery are
  not affected.

- **oats.aweb tests aw 1.36.58** (from 1.36.56, since oats.aweb 1.39.1); the
  floor stays aw 1.36.33. `aw-newer-than-tested` now warns only above 1.36.58, and
  `oats aweb setup --create --namespace` names and, with `--install-aw`,
  installs aw 1.36.58. Install that version on each host where readiness
  asks for it.
- **Stop an older wake broker before the new aw's starts.** aw 1.36.58's
  broker takes an OS file lock that an earlier broker doesn't hold. Rerun
  `oats aweb wake install` after the aw upgrade: it restarts the unit. A
  broker started by hand is stopped by hand first.

- **A deployment that runs `oats` as root, or as an operator account,
  against homes another user owns** must run those commands as the homes'
  owner, with that user's `HOME`: `sudo -H -u '#<uid>' oats session start …`,
  and the same for `oats instance stop`, `oats retire` and
  `oats instance upgrade`. Without `-H` the command may keep the caller's
  `HOME` and use the wrong `~/.oats`. A deployment where one user runs both
  `oats` and the agents, the team container among them, changes nothing.

- A legacy lock written before 0.69.15 without `processStart` may need a
  one-time operator clear after a container restart. OATS keeps an unknown
  holder held instead of taking it over: once no holder runs, clear the
  reported lock path and start again.

- **An older Desktop keeps appending the soul's role to a typed name until
  it is upgraded.** A Desktop of 0.69.17 or older still sends a typed
  `pricing-page` for `oats-desktop-expert` as `pricing-page-expert`,
  whatever OATS CLI it runs with: the CLI can't tell an appended word from
  one you typed. Upgrade the Desktop to get the name exactly as you type it.

- **A host on an older OATS keeps the old suggestion until it is upgraded:**
  a few words for the work, then the soul's last word. A spawn through
  `--server` with `--suggest-name` is named by the host that runs it, so its
  name follows the host's OATS, not the caller's.

## Changed

- The [team agent image](../container.md) pins `@awebai/aw` 1.36.58.

- **The Desktop accepts a newer CLI and says what it holds back.** Its tested
  bound is the minor of its own version, read from its own manifest; no
  release bumps a ceiling. A released CLI above that bound, with the same
  desktop API, is accepted with `aboveTested` and `testedThrough` on
  `/api/cli`. Reads, terminals, the Spawn preview and apply, Start, Restart,
  the colour and the background stay on. Every other operation, including
  one that does not exist yet, is refused before any CLI process runs, with
  code `cli-above-tested`; the launch resume sweep is skipped with one log
  line naming that code. In the CLI card's place one line says why and what
  is off, and links that version's release:
  `This Desktop was tested with oats CLIs up to <X.Y>; the installed CLI is <version>. Stop, Remove, schedules, triggers and every other change except Spawn, Start, Restart, colour and background are off until you install OATS Desktop <version>.`
  The card's "This Desktop is older than the installed oats CLI" branch is
  now for a CLI of a newer desktop API only. The floor (0.26.0), the
  prerelease rule and the desktop API rule are unchanged
  ([OATS Desktop](../desktop.md), [the probe](../desktop-cli-api.md))
  (oats-project/oats#1879).
- **`oats update`'s line for a CLI of another minor or major version** now
  reads `An OATS Desktop older than <X.Y> holds actions back with this CLI.`,
  then the Desktop's own held-back sentence for that version, then
  `(An OATS Desktop of 0.69.17 or older refuses this CLI until then.)`. It
  replaces `OATS Desktop refuses a CLI newer than its own minor version: if you
  use it, install OATS Desktop <version> first.`
  ([Upgrading](../upgrading.md#either-order-works)) (oats-project/oats#1879).

- **The official catalog pins oats.aweb 1.41.0** (from 1.39.0, through 1.39.1
  and 1.40.0), and OATS's own workspace takes it. The aw floor stays 1.36.33;
  the tested aw is 1.36.58.
  - **A broker-delivered home needs a running broker** (1.40.0). A Codex or
    `delivery: session` home used to spawn with no broker running, and was
    then never woken. It is now refused at spawn and at each start.
  - **An interrupted join is settled.** A join killed after aw accepted its
    invite no longer leaves a membership the home doesn't know about: the
    join writes its intent ahead, and the next `oats aweb join`, `leave` or
    retire finishes or releases it. A start warns.
  - **The roster marks retired certificates.** `oats aweb roster` marks the
    certificates a retire on this host had to leave in a team whose
    controller key people hold, and prints the command the team's
    controller removes them with.
  - **A refused wake stream is named** (1.39.1, 1.41.0). With aw 1.36.58 a
    stream the server refused shows as `refused` and is retried; readiness
    reports it as `wake-stream-unavailable`, naming the phase, aw's cause and
    the next attempt.

  Nothing a deployment must change. The mirrors under `mirrors/oats-aweb*`
  are copied from the v1.41.0 tag
  ([oats.aweb's CHANGELOG](https://github.com/awebai/oats-aweb/blob/v1.41.0/CHANGELOG.md)).

- **A Codex or session-delivery machine starts its wake broker before the
  setup expert is spawned.** The getting-started skill's step 9 has a new
  last item: when the setup expert is woken by the host wake broker (Codex,
  or `delivery: session`), the person runs `oats aweb wake install` in
  their own terminal, or `aw wake run` as a supervised process where there
  is no service manager, and the agent goes on to the spawn only once
  `oats aweb wake status` reports the daemon running. oats.aweb refuses to
  spawn or start such a home while no broker runs, so the broker can no
  longer be left for the setup expert to install. `/oats-host-delivery`
  Choice 2 now says the same: a broker-delivered home is refused with
  `wake-daemon-not-running`, not left unwoken.

- **OATS Desktop's backend now requires the app's per-launch credential on
  every request, and listens on a private socket.** The app's main process
  starts its own backend server at every launch, always, on a Unix domain
  socket in a directory of its own (owned by you, closed to group and
  others), and hands it a fresh credential over a private pipe. Every request
  carries that credential; one without it is refused (`401`
  `E_UNAUTHORIZED`). The backend opens no TCP port, and the app never uses a
  server it did not start. The Host and Origin guards stay. See
  [Security posture](../desktop.md#security-posture).
- **The CLI binary is chosen only through the app's own file dialog.**
  **Choose oats…** saves the pick where the backend reads it at each probe;
  `POST /api/cli/reprobe` takes no binary (its body is `{}` or empty,
  anything else is `400` `E_BAD_ARGS`).
- **Starting the backend or the view harness by hand.** A developer starting
  `packages/desktop/server/oats-web.mjs` passes `--socket <path>` (in a
  directory you own with mode 0700) and `--token-file <path>` (a regular
  file you own, mode 0600, holding 43 base64url characters); the server
  refuses to start otherwise, and refuses `--port`. The dev harness
  (`renderer/harness-server.mjs`) takes `--api-socket <path>
  --token-file <path>` in place of `--api <url>` and prints its own URL,
  with a token of its own the page sends; `harness.html`'s `?api=` mode is
  gone. The steps are in `packages/desktop/README.md`.

- **The Desktop no longer appends the soul's role to a name you type.** In
  the spawn dialog, a typed name goes to OATS as typed, in lowercase:
  `desktop-improvements` stays `desktop-improvements`, and
  `Pricing-Page-Lead` becomes `pricing-page-lead`. The soul is shown beside
  the instance. What to name an instance is oats.core's rule (oats-souls,
  "Name the instance"): `<descriptive>-<role>`, the role being the
  instance's role in your coordination. The Name field's example now reads
  "e.g. pricing-page-lead". The 64-character limit applies to the typed name
  itself. A spawn on a server takes the typed name the same way. With an
  OATS older than 0.26.0 on either side, what you type is still a purpose,
  named `<soul>-<purpose>` ([Desktop](../desktop.md)).

- **`oats.framework` 1.25.0: `oats.core` 2.13.0 and `oats.setup` 2.15.2.**
  - `oats.core`'s `/oats-souls` and `/oats-operate` name an instance
    `<descriptive>-<role>`, with its role in the coordination last and
    nothing appended, at most five words. A suggested name follows the same
    form from OATS 0.69.18.
  - `oats.setup`'s `/oats-host-delivery` says that, from oats.aweb 1.40.0, a
    home the wake broker delivers to is refused at spawn and at each start
    while no broker runs. `/oats-onboarding` names `oats.okf` 6.0.3, the
    release the catalog pins.

  No capability needs a newer OATS.

- **A lifecycle command is refused on a home its user does not own.**
  `oats session start` (and a resume), `oats instance stop`, `oats retire`
  and `oats instance upgrade` run what a home contains: its hooks, its
  harness, the Git of its repositories. Run as another user they would lend
  that user's authority to whoever can write the home. Each now answers
  `E_HOME_NOT_OWNED` before it writes anything when the user it runs as does
  not own the home, with the two uids in `details` and the command to run
  instead. Root is refused like any other user. This is rule 3 of the
  [trust model](../trust-model.md#the-line), held by the kernel.

- **oats.core names an instance for its role in your coordination, not for
  its soul.** `oats-souls` "Name the instance" now says: `--name
  <descriptive>-<role>`, where the role is the new instance's role in your
  coordination as your landing rules and coordination skills name it
  (`lead`, `developer`, `reviewer`), or one word for what it does when there
  is no coordination; at most five words; nothing appended, since the soul is
  shown beside the name. It no longer tells agents to end a name in the last
  word of the soul's name (`desktop-improvements-developer` for a lead's
  developer, not `desktop-improvements-expert` for any expert soul). A task
  written for a spawn states the new instance's role in its first lines,
  because a suggested name reads it from there. `oats-operate` "Naming" points
  at that rule. `--purpose` (`<soul>-<purpose>`) and the numbered fallback are
  unchanged: schedules and triggers still name their runs that way. An
  instance spawned with an older oats.core keeps the old rule until it is
  respawned or its package modules are upgraded (`oats instance upgrade`).

- **The official catalog pins oats.okf 6.0.3** (from 6.0.2), and OATS's own
  workspace takes it. A lock that a recreated container left in a host
  cache can now be released by hand with `oats okf unlock --lock PATH
  --token TOKEN --host-gone HOST`, naming the owner's host exactly; nothing
  releases it on its own or by age. A concept merged without its id under an
  old node no longer refuses every proposal on its base (`W_ID_MISSING`), and
  the subject verbs warn `W_BASE_INVALID` on a base that fails validation
  instead of saying nothing. The generated mirror under `mirrors/oats-okf*`
  is finalized from the v6.0.3 tag
  ([oats.okf's CHANGELOG](https://github.com/oats-project/oats-okf/blob/v6.0.3/CHANGELOG.md)).

- **A suggested name now ends in the role the task gives.** `oats spawn
  --suggest-name` (a preview or an apply) and `oats instance suggest-name` ask
  the model for the whole name, `<work>-<role>`, with the role last, as the
  task gives it. The kernel keeps that name: nothing appends the soul's role
  any more. A reply for `oats-engineering-expert` of `pricing-page-lead` names
  the instance `pricing-page-lead`, not `pricing-page-lead-expert`. Over five
  words, or over 64 characters, the descriptive words nearest the role are
  dropped, and the role is always kept. A one-word reply is `invalid-reply`,
  and the instance is numbered as before. The JSON and the reasons are
  unchanged ([The suggested name](../desktop-cli-api.md#the-suggested-name-feature-spawn-suggest-name)).
- **`oats instance suggest-name --soul` no longer affects the name.** It is
  optional now. When given, it is still checked as a soul name's shape
  (`E_BAD_ARGS`), because installed Desktops send it.

- The team container starts a persistent wake broker before opening SSH or
  resuming agents. Its supervisor reports broker exits and stops host run
  before the broker, keeping delivery available while agents drain.
- Host-run shutdown gives active launches 10 seconds to finish, then fences
  new admissions and cancels owned work within a further 5-second phase
  before stopping agents. Interrupted launches retain their conservative
  unknown/reconcile accounting. The container still needs a 45-second stop
  window; the runtime's final kill is a failure boundary, not a clean stop.

- **OATS's own copy of the engineering template moves to template-v3.1.1: the
  lead leads the whole effort and delegates well.** This changes the texts
  this workspace's own souls are composed from, not the kernel or any package.
  - An expert leads its effort and decides who does each piece. "Build it
    yourself by default" is gone: the cases in `/plan-and-spec` decide, and
    neither is the default. Its briefing now says what an effort is and where
    it ends.
  - A helper is usually an expert, of the soul whose knowledge the task
    needs, the lead's own included. A developer or the code reviewer gets
    only a task about a named piece of code, and the code reviewer no longer
    reads a plan or a design in prose.
  - A lead may keep a standing specialist: a child that stays for the effort
    in one area, one closed task at a time, retired when the plan has no more
    work there. At most three at once.
  - Exploration is a task once it has bounds: the decision it serves, where
    to look, when to stop and what to send back.
  - The dispatcher says "one effort, one lead".
  - After a change to the landing rules, a lead tells all its running
    children, a standing specialist included, not only its developers
    (template-v3.1.1).

  A running instance keeps the texts it was spawned with; a new spawn takes
  these. `capabilities/TEMPLATE-RELEASE` records the release and its commit.

- **OATS's own copy of the engineering template moves to template-v3.1.3:
  instances are named for their task and role, and no child runs below a
  model floor.** This changes the texts this workspace's own souls are
  composed from, not the kernel or any package.
  - Every instance a coordination text spawns is named `<task>-<role>` with
    `--name`: the task first, and last the role it plays in the effort (lead,
    developer, reviewer, helper, specialist, maintainer, dispatcher), never
    its soul, which the sidebar already shows. Five words at most, the role
    included. A name is used once: when it is taken, the task's part gets
    more specific, a later review round carries its number
    (`<change>-r2-reviewer`), and a retired maintainer's successor puts its
    count before the role (template-v3.1.2, template-v3.1.3).
  - The landing rules set a floor for the models children run on, OATS
    children and native subagents alike: a Claude model of the Opus tier or
    above, an OpenAI model of the Sol tier or above, and in any other family
    its strongest tier. The floor comes before model diversity, and it binds
    the model a child would actually launch on: a soul's default or a
    machine's `souls.launch` override below it is not used, and the parent
    tells its person once. The template leaves the floor to each
    organisation; this is OATS's answer (template-v3.1.3).

  A running instance keeps the texts it was spawned with; a new spawn takes
  these. `capabilities/TEMPLATE-RELEASE` records the release and its commit.
  The catalog's rows for the research and the scientific research templates
  move to template-v2.1.2, which carry the same two changes.

## Fixed

- **`oats worktree add`'s `E_BRANCH_EXISTS` carries its remedy when it loses
  a race too.** When another `add` or another git makes the branch between
  the check before the tree is made and this add's `git switch -c`, the
  refusal's `details` now carry `clone` and `remedy` (`<instance>/<branch>`)
  beside `branch`, and its message names the remedy, as the earlier check's
  always did. Both are built in one place, so they stay the same. The change
  is additive. The [errors of `oats worktree add`](../desktop-cli-api.md#oats-worktree)
  now also say that a racing `add` can end in either code: a switch that
  meets the branch's ref lock while another git holds it answers
  `E_GIT_FAILED` with Git's message, because a lock left by a git that
  crashed looks the same and the branch does not exist yet. A caller that
  retries once the branch exists gets `E_BRANCH_EXISTS`, with its remedy
  (oats-project/oats#1865).

- Linux lock holders and readers use the kernel boot UUID consistently,
  including SSH commands and the entrypoint sharing a container's PID
  namespace. Unmarked PID sandboxes keep the host's boot string; holder
  liveness still requires a visible pid, without cross-namespace translation.
  Historical qualified UUIDs remain compatible with visible live holders across
  upgrades. Crash budgets and refusals carry across same-kernel container
  restarts; successful restores after a host stop neither consume nor reset
  that budget and cannot be suppressed by its ceiling. A validated
  current-start host-stop timestamp excludes downtime from the in-boot
  eligibility gap, preserving clean restores after more than 24 hours;
  other loss/refusal guards remain. See
  [Session recovery](../execution-targets.md#which-losses-come-back).

- **A routed spawn whose `oats` on the server was killed can be retried
  safely.** When the server's `oats` ended without an answer
  (`E_REMOTE_ENVELOPE`) the error did not carry the decision and the key of
  the attempt, so the same spawn run again created a second instance. It now
  carries them as a dropped link (`E_SSH`) does: the message ends with the
  fix, and `--json` has `error.details: {decision, idempotencyKey, fix}`.

## Removed

- **`OATS_DESKTOP_PORT`.** The Desktop's backend has no port to choose: it
  listens on the private socket the app makes for it. A launch that still sets
  the variable, to any value, gets one line on stderr saying that it is ignored.

- **Installing the kernel no longer installs pi's aweb extension and its
  harness dependencies.** The kernel never imported `@awebai/pi`; the aweb
  capability installs that extension into pi separately. The pi SDK remains
  a development dependency for adapter tests, at its existing version.

## Documentation

- **What the capability trust check checks.** [Capabilities](../capabilities.md#mental-model)
  and the kernel's own comment now say that trust is decided where the
  workspace declares a member or a package, and that the kernel's later check
  only confirms that what it runs is the copy made at spawn. The
  [trust model](../trust-model.md#the-line) names the one piece of the package
  that runs as root, the harness-credential receiver, and why rule 3 does not
  cover it. No behaviour changes.

- **[The trust model](../trust-model.md) says who OATS trusts with what.**
  Everything that runs as one operating-system user is one trust group, the
  kernel included. The page gives the five rules that follow, what OATS does
  not promise inside a group, and which keys are held outside it.
  [The team container](../container.md#one-team-one-trust-group) now states
  in full that a container is the unit of compromise and holds one team.
