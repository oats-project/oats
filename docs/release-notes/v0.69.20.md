# OATS 0.69.20

The official catalog pins oats.okf 6.2.0 and oats.framework 1.26.0. oats.aweb
stays 1.42.1. Retiring an old home whose recorded cleanup hooks cannot run is
now refused before anything stops, with `--force` as the named way out, and
the Desktop's Remove explains why. The team container gains an egress
component that routes only the services an agent needs. The Desktop shows an
instance's owning human. OATS's own copy of the engineering template moves to
template-v4.0.2.

## Upgrade

- **Either order of the Desktop and the CLI works** from a Desktop newer than
  0.69.17 ([Either order works](../upgrading.md#either-order-works)). A
  Desktop of 0.69.17 or older still goes first.
- **Package pins:** oats.okf 6.2.0 (from 6.0.3) and oats.framework 1.26.0
  (from 1.25.2). oats.aweb stays 1.42.1. `oats sync` takes them.
- **Retiring an old home can now be refused.** A home spawned before
  `capabilityRuntime`, or captured before 0.26, whose recorded retire hooks
  cannot run is refused with `E_UNIDENTIFIED_INSTANCE_HOME`, unless its record
  proves that no cleanup is owed. Clean up its external identities and
  memberships with the provider's tooling, then run
  `oats retire <instance> --force` (details under Changed).
- **Team-container deployments:**
  - After pulling the updated team agent image, recreate existing agent
    containers to apply the 50-second stop timeout. Acceptance refuses the
    previous 45-second timeout.
  - Deployment bundles default `team.registryRoute` to `external`. Existing
    deployments with a registry Compose service must set
    `team.registryRoute: local` before upgrading. External mode refuses a
    local registry service or an owned destination, and local mode must refuse
    a URL the local service does not serve.
- **Respawn instances** to take the new framework skills and this workspace's
  template-v4.0.2 texts. A running instance keeps the texts it was composed
  with.

## Added

- The Desktop's instance panel shows an instance's **Owning human** in its
  Lineage section when OATS reports a human its messaging identity is
  attributed to (`attributedHuman` on its status row, local or on a server).
  Instances keep their own names as their labels everywhere, and an instance
  with no human attributed looks as before
  ([An instance's owning human](../desktop.md#an-instances-owning-human)).

- The Compose egress boundary probe accepts `--json` for `{passed,receipts,error?}`
  output and an optional derived `namePrefix` for every temporary container.
  Receipts identify the name, image, network, confirmed creation and verified
  absence; stderr includes receipts and unverified names in either mode.

- Agent egress policies can declare a nonempty subset of aweb, logs, registry,
  secrets and signer. Targets and probe paths must match exactly. Namespace
  authority TXT records are required with registry and refused without registry,
  including messaging-only sets; the human origin is required with signer and
  refused without signer. Omission keeps
  the existing five-service compilation. The minimal Compose wrapper includes
  explicit IPAM and a read-only preflight that refuses failed observations and
  overlaps. Every subset retains the universal boundary controls; team-image CI
  builds and probes the full set and two messaging subsets. See the
  [container reference](../container.md#egress-component).

- The team-container deployment can build a non-root DNS/TLS egress image and
  extend its Compose service. It routes only the named aweb, Secrets, Logs, signer
  request and registry hosts, using pinned upstream addresses and profile-derived
  public namespace TXT records. There is no recursive DNS or mounted service key.

- The agent Compose fragment requires `AGENT_TMP_SIZE`, in positive integer bytes
  from the shared `agents.tmpSize` input, and applies it to the `/tmp` tmpfs. Its
  acceptance check refuses a missing or different limit.

- Optional fragments add a public CA file with two fixed trust settings, or
  operator-maintained bare Git mirrors at read-only `/mirrors`. Acceptance checks
  their exact mounts and refuses writable-state aliases, multiply linked CA files
  and arbitrary environment changes. The fixed public trust reaches the supervisor,
  broker, direct SSH commands and login-captured tmux panes while retaining normal
  public roots. No service credential or TLS verification bypass is added.

- Runtime acceptance proves the agent's own on-link gateway denial with live
  controls and a plain-versus-isolated bridge regression. The ingress probe checks
  every policy route over HTTP/1.1 and HTTP/2, with required full-policy inputs
  and valid 200 service controls. Owned routes require separate common-path log
  coverage before/after negatives and non-delivery for forbidden human authorities;
  known-name refusals require completed TLS. Partial signer-only CLI calls cannot
  emit the admission token.
  Both checks must pass before agents launch. Readiness and rendered policy alone do not establish
  isolation. See the [component contract](../../container/agent/egress/README.md).

- The egress component can enable two fixed external roles: Git HTTPS at
  `github.com` and model HTTPS at `api.anthropic.com`. Operator-selected public
  IPv4 DNS resolvers are required, with no default. Agent DNS still points only
  at the proxy. Each external connection rejects unsafe or deployment addresses
  and connects to a validated IP without resolving it again.
- External enforcement is exact SNI plus a public destination; it does not filter
  HTTP authorities, paths, methods or repositories, or prove non-delivery at a
  public backend. The five pinned service routes and owned-backend audit remain
  separate. Runtime checks add verified-TLS external controls and refused-name
  logging. Claude launch settings suppress ancillary traffic, whose actual host
  requirements still need a real authorized start and turn.

## Changed

- **`oats.framework` 1.26.0: `oats.core` 2.14.0, `oats.setup` 2.16.0,
  `oats.coordination-setup` 1.1.0.**
  - `oats.core`'s `/oats-operate` says that, from OATS 0.69.20, retiring a
    home whose recorded retire hooks cannot run is refused with
    `E_UNIDENTIFIED_INSTANCE_HOME` before anything stops, and that
    `oats retire <instance> --force` then removes the home, warning that the
    skipped hooks revoked nothing (#1953).
  - `oats.setup`'s `/oats-onboarding` pins `oats.okf` 6.2.0 for knowledge
    operations (#1945).
  - `oats.setup`'s `/oats-agent-permissions` example asks a person before
    `aw` runs with `--identity-home`, `--human` or `--team`, and no longer
    allows a bare `aw mail ack` (#1952).
  - `oats.coordination-setup` follows engineering-coordination template v4
    (#1943). A maintainer's green light is an option per lane, off by
    default. The landing rules list the lanes and their owners, and a lane's
    maintainer is found by its instance name, `<person>-<lane>-maintainer`.
    `VERIFIED at <head>` comes from whoever specified the work.

  No capability needs a newer OATS. The retire refusal is the kernel's own,
  and the skill names the version it starts in.

- The team agent image pins the released OATS 0.69.19 dependency closure,
  removing the unused pi extension subtree from the image lock. The other
  committed CLI packages and their integrity pins remain unchanged.

- The agent supervisor lets the wake broker finish its five-second channel
  delivery drain before escalation. Broker cleanup allows six seconds and
  sshd cleanup keeps three seconds; container acceptance requires a 50-second
  stop grace for the kernel and supervisor phases. The runtime deadline is a
  final failure boundary for stuck OS work; wake delivery and model activity
  require separate evidence.

- **The official catalog pins oats.okf 6.2.0** (from 6.0.3, taking 6.1.0's
  changes with it), and OATS's own workspace takes it. A knowledge change
  names the agent that proposed it in Git trailers on its commit, and
  `oats okf propose --apply` checks `gh` before it pushes anything,
  refusing `E_GH_UNAVAILABLE` with the fix (6.1.0). New in 6.2.0: an
  optional, host-only setting `settings.oats.okf.github-token-file` (in
  `oats-local.yaml` only) gives every remote `git` and `gh` call of oats.okf
  the token in that file, for knowledge writes from a container; with it, a
  publication refuses `E_HOST_CREDENTIAL` while the host could answer GitHub
  in the token's place. `oats okf setup --check --soul <soul>` says whether a
  deployment is provisioned for knowledge and names each fix
  ([Bringing up a deployment's knowledge store](https://github.com/oats-project/oats-okf/blob/v6.2.0/README.md#bringing-up-a-deployments-knowledge-store)).
  Without `github-token-file` nothing changes, apart from the `gh` check
  before a push. Three things are not yet proven in a live run: a proposal
  opened through `github-token-file` on a real private repository; GitHub
  refusing that write-role-only credential a direct push and a merge under
  the example ruleset; and what GitHub reports for such a token, which
  `setup --check` reads. A container deployment that relies on
  `github-token-file` waits for that run. The generated mirror under
  `mirrors/oats-okf*` is finalized from the v6.2.0 tag
  ([oats.okf's CHANGELOG](https://github.com/oats-project/oats-okf/blob/v6.2.0/CHANGELOG.md)).

- The shared ingress probe accepts an explicitly external registry with a harmless
  verified-TLS 200 control at every pinned address over HTTP/1.1 and HTTP/2. It
  reports positive connectivity only, without third-party refusal or backend-log
  claims. The other four service routes and signer/human authority refusal keep
  their full owned-backend audit. External registry addresses must not overlap
  deployment destinations; no new route or forwarding policy is added.

- Retiring homes spawned by a kernel from before `capabilityRuntime`, and
  captured homes from before 0.26, now refuses with
  `E_UNIDENTIFIED_INSTANCE_HOME` if their hooks cannot run and the record
  does not prove no cleanup is owed. Both `--plan` (including Desktop Remove)
  and apply refuse before anything is stopped, run or removed, children included.
  Inspect the home, clean up external identities/memberships using the provider's
  tooling, then run `oats retire <instance> --force`. Force keeps the warnings
  that hooks did not run and state was not revoked; it can leave external state
  active after deleting the local credential. Captured homes need positive
  evidence that no capability's spawn hook ran to retire without force.
  Forced self-retirement keeps the force choice in its deferred completion.

- Retire plans for a home that cannot be entered (mode 000), or an
  interrupted spawn's stub without recorded hook bindings, now refuse with
  the same cleanup admission as apply. This is the before-effects plan/apply
  rule; a refusal returns no plan claiming that work is absent. The stub's
  refusal now names missing `capabilityRuntime` and retains the `--force`
  remedy. Homes lacking workspace modules alone are not newly refused:
  the cleanup rule depends on their recorded hook bindings.

- Retire hooks now run in the repository Git identifies for an instance's
  own worktree when its record names no `repo`. Previously that home ran no
  retire hook and warned that there was no context repository. Retirement
  now performs the recorded cleanup in the Git-derived context without
  rewriting the instance record.

- **OATS's own copy of the engineering template moves to template-v4.0.0,
  taken up whole.** The template recomposed every text, so the copy is
  template-v4.0.0's text with OATS's answers and its marked adaptations
  written back in. This changes the texts this workspace's own souls are
  composed from, not the kernel or any package contract.
  - **One agent is the default,** and every expert instance holds one seat,
    named on a `Seat:` line in its task: root lead, specialist, or helper or
    probe. A lead sizes the tree to the work: alone, with short-lived probes
    and helpers, or with one long-lived specialist per area for a large
    effort or one across several areas.
  - **Skills renamed or folded in.** `oats.engineering-expert` has five
    skills: `/plan-and-spec`, `/orchestrate-agents` (was `/send-a-helper`),
    `/coordinate-developers` (takes in `/verify-developer-work`),
    `/hand-off-and-ask` (takes in `/hand-off`, `/ask-a-person`,
    `/findings-and-blocks` and `/across-people`) and `/land-on-agreement`
    (takes in `/find-the-maintainer`). `oats.build` has three:
    `/build-in-the-repository` (new), `/run-the-review-loop` and
    `/work-the-reviews`; `/test-first`, `/diagnose-before-fixing`,
    `/design-while-writing`, `/execution-strategy`, `/prove-it-works`,
    `/maintain-dev-docs` and `/worktrees` are gone. `oats.developer` folds
    `/understand-the-spec` into its briefing. `oats.maintainer` has
    `/keep-the-lane` (from `/maintainer-intake`, `/keep-it-clean` and
    `/cross-review-peer`), `/plan-and-ship-release` (from `/plan-release`
    and `/ship-release`), `/pr-review`, `/direction-gate` and
    `/launch-work`; it still drops `/support-maintainer`. `oats.landing-rules`
    gains `/landing-rules-detail` and `/wait-and-retire`, which every
    coordinating soul now has. The souls' own texts name the new skills.
  - **A lane maintainer's green light.** In the template it is an option a
    lane chooses. Every OATS lane asks for it: the maintainer's read of a PR
    from an effort is now its verdict at the exact head, `GREEN LIGHT`,
    `RETURN` or `ESCALATE`, on direction, contracts, coherence, scope and
    evidence. Each lane's agreements are as before: the PR's second reader,
    the release lane's sign-off where the lane asks, and the merge where the
    lane's arrangement puts it. A PR with no lead still gets the four gates.
  - **Both maintainer reads look at the code and judge direction, roadmap
    and product fit.** The lane maintainer's green light adds its own read
    of the whole diff, from its own checkout, to the five checks: a defect
    it finds there blocks, and it runs no review rounds of its own. The
    release lane's sign-off keeps the four gates (direction, roadmap and
    product fit; correctness over the whole diff; security; mergeability)
    on every PR it signs off, at the exact head being merged, as the final
    gate on main.
  - **What carries to a new head.** A review carries as before, except that a
    fix to a minor is read by the review bot where one runs, otherwise by a
    fresh reviewer briefed with the delta, not by the round's reviewer. A `VERIFIED` note and a green light carry only
    through an unchanged rebase or update; at any other head, whoever gave
    one reads the delta and gives it again.
  - **Every finished instance retires itself,** its children first
    (`oats retire <name> --self`), and its parent checks that it is gone and
    retires one still listed. A reviewer retires itself once its report is
    sent: one reviewer, one report.
  - **OATS keeps its lane map.** The template drops it; OATS's landing rules
    still point at the pinned issue "Lane map for awebai/oats" for its lanes,
    their owners and arrangements, and a lane's maintainer is found by its
    `active` entry there. Maintainers keep their instance names.
  - The model floor, the hosts rule and CI as the test run are stated once,
    in the landing rules' house rules.

  A running instance keeps the texts it was spawned with: composition is
  frozen at spawn, so no running instance changes, and a new spawn takes
  these. `capabilities/TEMPLATE-RELEASE` records the release and its commit.
  The catalog's row for the engineering template moves to template-v4.0.0.
- **`oats.framework`'s setup expert teaches the green light as an option.**
  `/set-landing-rules` offers a lane maintainer's green light per lane, off by
  default: recommended for a large project (several lanes or maintainers,
  several people), left out for a small personal project. Its carry rule
  follows template-v4.0.0. `/adapt-to-the-organisation` and
  `/design-the-roster` write no lane map: the landing rules list the lanes and
  their owners, and a maintainer is found by its instance name,
  `<person>-<lane>-maintainer`.

- **OATS's own copy of the engineering template moves to template-v4.0.2.**
  The two patch releases fix how a lane's maintainer is found and started.
  The copy takes them in, adapted to the lane map, where a lane's maintainer
  is still its `active` entry. This changes the texts this workspace's own
  souls are composed from, not the kernel or any package contract.
  - **A refused spawn means the seat is held.** When `oats spawn` refuses a
    maintainer's name because it is taken, a holder is running or stopped.
    The dispatcher, the expert and the maintainer each find it and start
    none under another name.
  - **A new maintainer gets a name no instance has had.** The kernel accepts
    a retired instance's name. So before starting one, the dispatcher and
    the expert check each name of the family in turn with
    `oats instance events <name>`, and the maintainer's launch-work says to
    do the same. A name the roster still lists counts as used.
  - **A maintainer named only on the roster is asked about first.** Such a
    name may be retired or running elsewhere. The dispatcher, the expert and
    the maintainer ask their person before starting another.
  - **The dispatcher handles the expert's other cases too.** In another
    person's lane, it asks their dispatcher, or that person. Where the
    workspace has no maintainer soul, or it can't tell the lane or its
    owner, it asks its person. In each case it starts none.
- **The maintainer soul's OATS review skill agrees with `pr-review`.** It
  names the four gates for the release lane's sign-off as well as for a PR
  with no lead, and the green light's read of the whole diff.
- **The official catalog** lists template-v4.0.2 as the engineering
  template's latest release.

## Fixed

- Canary and TCP-control cleanup checks exact-name absence, including after Docker
  timeouts, and removes a container only when its per-attempt ownership label
  matches. Name collisions and failed observations refuse admission without
  removing another caller's container. Diagnostics distinguish confirmed leftovers
  from unowned or unverified names, including collisions. The host-side helpers remain outside the
  egress image build context.

- The egress ingress routine names its signer-role requirement before sending
  controls when given a policy without signer. Runtime boundary controls now
  share the compiler's canonical role order, including in emitted probe
  programs. The packaged CLI keeps its values-withheld refusal diagnostic.

- Desktop's Remove refusal now explains when OATS cannot tell what a home's
  capabilities created or cannot run their cleanup. The headline says
  nothing was removed and points to Details for the kernel's cause and
  remedy. It never suggests forcing an unreadable record: that case needs
  the file restored. Force commands appear only in Details where the
  kernel offers them. Stop keeps its existing refusal text.

- Conversation capture stops before sealed aw client-log entries, preserves
  the cursor, and reports them as sealed instead of failed projections.
  Command capture sets the input aside as “sealed, not readable by this recorder”.

- Capability commands routed with `--server` refuse `--invite <token>` and
  `--invite=<token>` before ssh starts. Use `--invite-stdin` and a pipe instead.
- The agent-permissions setup example asks before `aw` selects another identity,
  human principal or team, and leaves mail acknowledgement to the classifier.

## Removed

- Removed the recorder's unused signature-verification helpers
  `base58Decode`, `publicKeyFromDidKey`, `base64DecodeLoose`,
  `verifyDidKeySignature` and `verifyTurnSig` from the `@awebai/turn-record/canonical` export.
  `@awebai/turn-record` lives in this repository and is not published to npm.
  An importer of a local copy must remove those imports or use a
  signature-verification library. No in-repository production callers used
  them. Source signatures are still preserved.
