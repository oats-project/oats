# OATS 0.69.21

The official catalog pins oats.aweb 1.43.0: a private aw registry is admitted
by one host setting, aw children no longer take exported selectors, and grant
seats stay in their recorded team. Instances can be pinned to the top of their
machine's list (`oats instance pin`). The Desktop's sidebar is reworked: two-line
rows, groups that start collapsed, no lineage lines, and a new foot. The
getting-started skill sets up a workspace on the person's own aweb server.

## Upgrade

- **Either order of the Desktop and the CLI works** from a Desktop newer than
  0.69.17 ([Either order works](../upgrading.md#either-order-works)). A
  Desktop of 0.69.17 or older still goes first.
- **Package pin:** oats.aweb 1.43.0 (from 1.42.1). oats.framework stays
  1.26.0 and oats.okf 6.2.0. `oats sync` takes it.

What a deployment must change, from oats.aweb's 1.43.0 entry:


- **On a non-public aw registry:**
  1. Run `oats aweb setup --registry <origin>` in the deployment.
  2. Rerun `oats aweb resident create <name>` for each resident.
  3. Run `oats aweb wake install` from your own shell.
  4. Restart the homes.

  Until then, setup, spawn, join, launch and readiness refuse with
  `registry-setting-required`. A deployment on the public registry changes
  nothing.
- **Exported aw selectors no longer reach aw:** `AWEB_IDENTITY_HOME`,
  `AWEB_URL`, `AWEB_API_KEY`, `AWEB_ROLE_NAME`, `AWEB_ROLE`,
  `AWID_REGISTRY_URL`. If you exported them for ordinary lifecycle commands,
  record the service in the selected aw home instead, and a private registry
  in the setting above.
- **Grant seats:**
  - A grant seat with `.oats-aweb/seat.json` whose `identity.resident` or
    default team has changed refuses start: respawn it.
  - A home that an earlier release renewed into another team needs the
    printed manual revoke, then `oats retire <instance> --force`.
- **Retained seats:** a symlinked `identity.source`, or a link or special
  file in the copied authority, now refuses. Point it at the real directory.
- **Scripts:**
  - `oats aweb setup --check-only --json` answers `member:null` with a nonzero
    exit when the membership can't be read.
  - `join --plan` fails with `E_SETUP_MEMBERSHIP` for an unreadable root.
  - `setup --create`, and `setup --join` without a token, refuse while the
    default root's membership can't be read.
  - An unavailable username fails as `E_SETUP_USERNAME_UNAVAILABLE`, where it
    was `E_SETUP_NATIVE`.

**Respawn instances** to take the new oats.aweb module, or move a stopped
home with `oats instance upgrade`. A running instance keeps the module it was
composed with.

## Added

- **The `oats-getting-started` skill sets up a new workspace on the
  person's own aweb server** (#1774, #1775). Step 1's messaging line names
  hosted aweb as the default, "unless you run your own aweb server". The
  own-server answer collects
  three things, none of them secret: the namespace domain the person
  controls, the server's public URL, and whether the server uses the public
  AWID registry. A server on a private registry is not set up yet: the
  branch stops before writing anything, says it needs `oats.aweb` with
  `oats aweb setup --registry` (awebai/oats-aweb#284), and offers hosted
  aweb. It also names the prerequisites, which stay on the person's side:
  the namespace's controller key on this computer, its `_awid` DNS record,
  and the server reachable. Then:
  - The skill reads the version `oats.aweb` was tested with (`tested` in
    its `aw-compat.json`, read at the catalog's exact `oats.aweb` ref, never
    `main`) and compares the installed `aw` with it, in `oats.aweb`'s own
    version order. A missing or older `aw` is replaced by `tested`: the skill
    checks the version `aw` prints, and that the program `file` reports is
    for this machine's architecture. A newer `aw` is kept, since another
    deployment may need it, and the hand-over says "aw X is newer than the
    tested Y; kept". On an OATS release whose `oats.aweb` is older than
    `v1.42.1`, the branch stops and offers hosted aweb.
  - The workspace commits the team `<workspace>:<namespace>` as its only
    team and its default. It writes no hosted `default:…aweb.ai` team and no
    `localTeams`.
  - Step 9 checks the DNS record read-only
    (`aw id namespace check-txt`), then creates the team with
    `oats aweb setup --create <workspace> --namespace <domain> --name <workspace>-root`,
    registered with the person's server. It reports where the team key
    lives (the path, never the key), and checks membership before the
    spawn.

  The skill never makes the namespace's controller key, and never asks for
  `AWEB_API_KEY`. Hosted aweb is unchanged: it installs the latest `aw` and
  records its version. The join of an existing workspace and the machine
  found-list are unchanged, and don't offer the own-server branch.

- **Pin an instance at the top of its machine's list** (feature `instance-pin`).
  `oats instance pin <instance> on|off` records or removes the pin, locally or
  with `--server`. Its answer is `{ instancePinApi: 1, instance, home, pinned,
  changed }`; `home` names the home it resolved, so a routed or `--home` pin
  says which one it pinned.
  - The pin is shared. It is kept in the instance's home, so everyone who views
    that machine sees it: the Desktop, the TUI and another machine's routed
    view. There is no per-viewer pin.
  - The home keeps it in `.oats-pinned.json` through restart, stop, resume and
    `oats instance upgrade`, and a retire removes it with the home. Retire never
    counts the file as work, and a capability cannot declare it.
  - `pinned: true` appears on `oats status --json` rows, on `oats server roster
    --json` rows (only when the host's row says exactly `true`) and on
    `oats inspect --home`. The key is absent when the instance is not pinned.
  - No spawn flag or `soul.yaml` key pins an instance: a pin is a person's
    choice about the view. A routed pin needs a host that lists `instance-pin`.

  See
  [Pinned instances](../desktop-cli-api.md#pinned-instances-oats-instance-pin).

## Changed

- **Getting started names an unavailable aweb username.** With an oats.aweb
  that answers `E_SETUP_USERNAME_UNAVAILABLE` (awebai/oats-aweb#286), the
  `oats-getting-started` skill's signup step knows that nothing was created:
  it asks the person for another `N`, or, on a machine found-list, tells
  them why and stops. `E_SETUP_NATIVE` no longer reads as "most likely
  taken"; on an older oats.aweb a taken `N` still fails that way.

- **The catalog pins oats.aweb 1.43.0** (awebai/oats-aweb, tag `v1.43.0`), up
  from 1.42.1. It still requires OATS >=0.68.0; the aw floor stays 1.36.33 and
  the tested aw 1.36.58.
  - **Registry admission is one host setting.** A private aw registry is
    admitted only by `settings.oats.aweb.registry`, which
    `oats aweb setup --registry <origin>` records in `oats-local.yaml`. A saved
    `registry_url` and an exported `AWID_REGISTRY_URL` are locators only.
  - **aw children ignore exported selectors.** Each takes only what a call
    passes by name. A malformed `OATS_SETTINGS` refuses instead of using
    defaults.
  - **A grant seat's calls stay in its recorded team,** and its
    `.oats-aweb/seat.json` owns that team. An empty grant seat now completes
    retire with the documented `nothing-to-delete` outcome.
  - **Membership and custody reads fail closed.** An unreadable read is
    unknown, never "not a member".
  - **Setup** names an unavailable username, and points a new account at
    `claim-human`. `--invite-stdin` reads the token without echo on a
    terminal, and `oats aweb invite --out <file>` writes it to a new
    owner-only file.

- **The Desktop's sidebar reads more calmly.** An agent's row is two lines: its name, then its soul and the machine it runs on ("oats-expert · falcon": this computer's own rows by its `host.name` in `oats-local.yaml`, else "This Mac"), in a 44px row with its dot centred. The repository, branch, pull request and harness badge are no longer on the row, and the row has no hover card and no tools on hover: the instance panel shows the repository, branch, harness and model, and a new **Needs input** section with the reason an agent waits, how long it has waited and its message; the row's context menu (right-click, Shift+F10 or the Menu key) opens its pull request (**Open pull request…**) and starts a stopped agent (**Start…**). Until the panel serves an agent whose terminal isn't open, the row's tooltip says its repository, branch, harness and model; with the keyboard alone those show once its terminal is open. The roster draws no lines between agents any more: a child is indented under its parent, a little space separates each group from the next, and a screen reader hears "under <parent>" (with "same work" for a child doing its parent's work) and "sibling of <name>". The order and the needs-input marks are unchanged, and the command palette keeps its lines. **Workspace overview** and **Automations** are pinned rows under the list of workspaces, and **Automations** shows a red dot, which a screen reader hears as "a run failed", while a schedule's last run failed. The foot shows **N need you** (it takes you to the first agent that needs you), **New agent** and **?** (the keyboard shortcuts). An empty roster says "No agents yet" and the key that starts one. The CLI and the docs still say "instance". See [the sidebar](../desktop.md#workspaces) and [its instance tree](../desktop.md#the-sidebars-instance-tree).

- **The Desktop's sidebar shows the top-level instances only until you open one.** An instance with children has a chevron before its name, with the number of instances under it. Click the chevron to show or hide its group; a click elsewhere on the row still opens its terminal, and Right and Left still open and close the focused row. Every instance at the top of the tree starts collapsed in each new window (except one still being set up or retired, or whose retire failed, which stays open), and an instance inside a group starts open. A collapsed instance still shows "! N below" for the hidden instances that need input. **Show in roster**, `--instance` and a spawn from the Desktop open the rows above the instance they show. The TUI's list is unchanged and still shows every instance open ([The sidebar's instance tree](../desktop.md#the-sidebars-instance-tree)).

## Fixed

- **The getting-started skill reads a failed join from what ran.** Its last messaging check (step 9, item 5) no longer says a run left the root outside the team when no root was made. After the signup or the labelled join it says no root was made or recorded, and a team create that recorded no root is rerun unchanged. Before the person's join window opens, the agent lists the per-team roots and compares the list afterwards, so a root from an earlier join is not read as this one. It compares the team's label as the provider writes the folder name: lowercase, `_` and `.` as `-`. When the window shows no `E_SETUP_` code, the agent asks for the window's last line. The agent still never sees the join's output, never reruns it, and asks for no secret ([#1746](https://github.com/oats-project/oats/issues/1746)).

## Removed

- **Show only the current workspace.** The list of workspaces always shows every workspace: the toggle, its ⌥⇧⌘O / Ctrl+Alt+Shift+O (which reaches a terminal's program again) and its palette command are gone, and a choice saved for it is ignored.
- **The sidebar's settings cog, its Hide sidebar button and its brand mark.** Theme, font and keyboard shortcuts are in the command palette (**Theme: choose…**, **Font: choose…**, **Shortcuts: edit keyboard shortcuts…**) and on the foot's **?**; the sidebar still hides with ⌘B / Ctrl+Shift+B, the palette's **Sidebar: toggle (hide/show)** and **Show sidebar**.
