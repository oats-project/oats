## Changed

- **`oats.framework` 1.23.0 adds `oats.coordination-setup` 1.0.0 and carries the coordination texts.** The new capability gives the setup expert OATS's coordination practices and how to shape them to one organisation: the roster of souls, the landing rules and when to revisit them. Its entries in these notes describe it. `oats.onboarding` 1.3.0's `/oats-tailor-workspace` starts coordination from OATS's template repositories. `oats.setup` 2.14.0's `/oats-package-pins` says to run doctor after a pin change, check `souls.disabled` by hand and check a reviewer soul's model. Its `/oats-teams` names the `<prefix>/*` pattern warning, and its `/oats-setup-model` names the new capability. `oats.core` 2.12.2's `/oats-souls` uses the new roster's names in its examples, and `oats.support` 1.0.2's `support-handoff` works without `/support-maintainer`. The lines that need this release say so: the catalog's "Coordination templates" section, the pattern warning and doctor's `souls.disabled` report are from OATS 0.69.13. No other command they name needs a newer OATS than each capability already admits.
