## Changed

- **Onboarding starts coordination from OATS's template repositories.** Coordination ships as templates, not packages. `/adapt-to-the-organisation` and `/oats-tailor-workspace` now start each group from the closest template repository at a `template-v*` tag and follow its `ADAPTING.md`; the first is `oats-project/oats-engineering-coordination`. Each copied capability records the template release it came from. `docs/official-catalog.md` lists the templates under "Coordination templates".
- **The package `oats.engineering` is frozen at v1.18.0.** Existing pins keep resolving through its catalog entry and aliases; its repository gets no further releases, and the engineering template lives in its own repository.
- **The coordination practices spawn children as OATS instances.** `/coordination-best-practices` now says to launch probes, developers and reviewers as OATS children rather than as the harness's own subagents (in Claude Code, pi or Codex), except in a multi-agent workflow mode such as Claude Code's ultracode. A child that checks work (an adversarial review, an investigation, a validation) runs on a different model from the agent whose work it checks, and the developer, not the expert, launches its fresh reviewer for each round.
