# OATS 0.70.8

Unreleased

A security fix and two kernel features for agents' status, with package pins.
`oats session input` to a tmux agent no longer answers its permission prompt,
and two inputs to one agent no longer run together. An agent's status row says
whether it is working on a turn or idle (`activity`). A session provider's
check is told the model and its warnings reach a person. Pins move to
oats.aweb 1.49.2 and oats.framework 1.31.0 (oats.core 2.17.0). The Desktop
runs its renderer sandboxed. Team images and the egress probe gain split-host
proofs.

## Upgrade

- **Upgrade the CLI before `oats sync`**, so that the catalog's new pins
  resolve. The Desktop and the CLI can be upgraded in either order.
- **OATS pins oats.aweb 1.49.2** (from 1.49.1) **and oats.framework 1.31.0**
  (from 1.30.0; oats.core 2.17.0). Their floors don't move. Running instances
  keep the modules they were spawned with: respawn them, or move a stopped one
  with `oats instance upgrade`, to take the new ones. A Claude Code home
  reads `activity` only once it has oats.core 2.17.0's hooks.
- **`oats session input` to a tmux home now takes a lock under `~/.oats`.** A
  caller that may not write there, such as a process inside a sandbox, is
  refused `E_SESSION_INPUT_FAILED` with nothing sent, where its input was
  typed before. Agents message each other through aweb, whose broker runs on
  the host, so that path is unchanged.
- **An input over a permission prompt is refused** `E_SESSION_PROMPT_OPEN`.
  A script that typed to an agent at a prompt must let the person answer it
  (`oats session attach`, or the client's prompt card). Read feature
  `session-input-permission-refusal` to tell the refusal from a lost input.
- **The package names the turn record's Node requirement.** `engines.node`
  is now `"^22.13.0 || >=23.4.0"`: Node 22.13+ on 22.x, 23.4+ on 23.x,
  or a newer major. npm now warns at install on Node 22.0–22.12 and
  23.0–23.3, where the turn record cannot load `node:sqlite` without an
  experimental flag. The CLI still runs on those versions; its
  `E_NODE_UNSUPPORTED` refusal remains only for Node below 22.

### Team images and the egress probe

- Compose boundary plan writers must add integer `"schema": 1`. Missing schema
  now refuses with `E_EGRESS_PLAN_SCHEMA: this probe reads runtime plan schema 1 (local) or 2 (split); found none; regenerate the plan with schema: 1 or schema: 2`.
  Unknown numeric schemas substitute their value for `none`; other types report
  `invalid <type>`. No missing-schema fallback exists. This refusal occurs before
  engine access, exits 1 and is printed on stderr (including with `--json`).
- Image builds must pass `--build-arg TEAM_IMAGE_SOURCE_SHA=<full commit SHA>`;
  missing or malformed source pins fail. Build egress from `container/agent`
  with `-f container/agent/egress/Dockerfile`, using its Dockerfile-specific
  allowlist. Extract each image into its own directory and preserve the tree
  hierarchy; egress scripts and fragments live below `egress/`.
- Optional acceptance inputs set to `""` mean unset; include optional mount
  fragments only for non-empty sources. Every deployment creating its own
  agents/services networks must run the extracted `egress/preflight-network.mjs`
  immediately beforehand with all six network inputs and require exit 0 before
  sourcing its output or creating networks; remote contexts refuse.
- Consumers must refuse agent/egress pairs with different manifest source
  commits or different shared-file hashes. Acceptance now checks resolver
  readability and non-empty content as the runtime UID; failure is
  `E_AGENT_RESOLVER: /etc/resolv.conf must be readable and non-empty by the runtime UID`.

- Existing deployments change nothing: an absent `humanRole` retains the signer
  rule and generated proxy/DNS bytes. A bundle setting `humanRole` needs the new
  egress image; older images refuse the field.

- Nothing for schema-1 plans: their behaviour and JSON are unchanged. An
  unknown schema's refusal now names both versions:
  `E_EGRESS_PLAN_SCHEMA: this probe reads runtime plan schema 1 (local) or 2 (split); found <x>; regenerate the plan with schema: 1 or schema: 2`.
  A wrapper that matches the old text must match the new one. Probes older than
  this release refuse a schema-2 plan with their schema-1 text.

## Added

- Agent and egress images carry root-owned deployment fragments and standalone
  probe import closures under `/opt/oats/deploy`, with a schema-1 `manifest.json`
  binding every file's SHA256, source commit and installed CLI versions to the
  image digest. Egress includes the documented `compose.minimal.yaml` input and
  its network preflight. See the [run contract](../container.md#run-contract)
  for extraction, verification and runtime inputs. Committed image pins are
  OATS 0.70.7, aw 1.36.59 and Claude Code 2.1.322; publication stays disabled.

- Egress policies may set `humanRole: "secrets"` to prove human-console refusal
  without signer. Declared roles must include secrets and exclude signer, and
  `humanOrigin` is required. Secrets API and console may share a backend and log;
  ingress admission still requires refusal before any forbidden backend delivery.
  The ingress and boundary reports name the anchor.

- **A session provider's check is told the model, and its warnings reach a
  person** (feature `launch-model-and-check-warnings`, #2122). The launch a
  provider's `check` is asked about now carries `model` when the launch names
  one (`--model`, a launch configuration's, the soul's or the host's resolved
  one), and has no `model` key otherwise. A provider can so refuse a model
  its harness cannot resolve in its check, which a `session restart` asks
  before it stops anything: the running agent keeps running, where a refusal
  at the provider's launch left it stopped. What a `ready` check warns of is
  no longer dropped: each warning is one line in the `warnings` of
  `oats spawn --preview`, `oats launch-config preview --home`, `oats spawn`,
  `oats session start` and `oats session restart`, naming the capability and
  the verb, with the provider's code and message. The lines are text for a
  person, never parsed
  ([desktop-cli-api.md](../desktop-cli-api.md#relayed-check-warnings),
  [capabilities.md](../capabilities.md#check-optional)).

- **A Claude Code agent's row says whether it works on a turn or waits**
  (`oats.core` 2.17.0, [#2122](https://github.com/oats-project/oats/issues/2122)).
  oats.core's Claude Code hooks record each turn's boundary in
  `<home>/.oats/turn.json`, which a kernel that lists `status-activity` reads
  as the row's [`activity`](../desktop-cli-api.md#row-activity):
  `UserPromptSubmit` writes the turn's start, a launch prompt's included;
  `Stop` and `StopFailure` its end; and Claude's `idle_prompt` notification
  ends a turn whose end no hook reported
  ([the turn record](../capabilities.md#oatscore-the-turn-record)). Nothing is
  written for Codex, whose row reads `null`. Claude Code reports no
  interrupt (Esc), so a Claude Code row reads `null` from 30 minutes into a
  turn with no end. A home takes the hooks at its next start once its
  oats.core is 2.17.0: a new spawn, or `oats instance upgrade`. The hooks
  write a file an older kernel never reads.

- **A running agent's row says whether it works on a turn or waits at its
  prompt** (feature `status-activity`,
  [#2122](https://github.com/oats-project/oats/issues/2122)). `oats status
  --json` instance rows and `oats server roster --json` rows gain `activity`:
  `"working"`, `"idle"` or `null` where OATS cannot tell
  ([`activity`](../desktop-cli-api.md#row-activity)). The key is only on a
  row whose session is there, and no act reads it. A tmux row that runs reads
  the last turn boundary its harness wrote into `<home>/.oats/turn.json`,
  counted only from the row's `startedAt`: `@awebai/oats-pi` writes it for pi
  from this release, and oats.core 2.17.0's hooks for Claude Code (in
  oats.framework 1.31.0, pinned by this release); until an instance has both this kernel and such a
  writer its row reads `null`, and a Codex row always does. A Claude Code row
  whose turn started more than 30 minutes ago with no end reads `null`,
  because Claude Code reports no interrupt. A provider row carries its
  provider's own answer, the new optional `activity` key of `inspect` and
  `inspectMany` ([capabilities.md](../capabilities.md#inspect-and-inspectmany));
  a provider that sends none reads `null`. An older client ignores the field.

- The egress boundary probe takes plan schema 2 for an agent host whose
  services run on another host. It proves, from the isolated agent and the
  proxy's outward bridge, that the one declared services-host address refuses
  TCP on the Redis port, and on the PostgreSQL port when PostgreSQL runs there.
  An external PostgreSQL at its own pinned address must be denied IP-wide by
  the policy and refuse the isolated agent; the outward bridge's result for it
  is recorded, not required, since the database's credentials protect it from
  other hosts. The `--json` document adds `mode:"split"`, the wrapper's `run`,
  the deploy copy's `sourceCommit` and the four role-by-vantage results, each
  naming the address it tested and whether it is required. A new services-host
  witness, `egress/probe-services-backends.mjs`, selects the Redis container,
  and the PostgreSQL container when it runs on the services host, by their
  Compose labels and proves them running, healthy, unpublished and reachable
  from their own networks; it does not attest an external PostgreSQL. It
  reports the Docker Engine version, since engines before 28.0.0 can allow direct
  routed access to unpublished container ports, and its refusals name the fix
  (a missing healthcheck, the number of matching containers found). Both run
  only from a deploy copy extracted from the egress image. `policy.mjs` exports
  `policyHash`, a canonical policy hash with a cross-language test vector. The
  proxy now records the hash of the policy it loaded at startup in
  `/tmp/egress/policy.hash`, and a split proof refuses with
  `E_EGRESS_POLICY_STALE` when the running proxy loaded a different policy
  than the plan: recreate the proxy after changing its policy. See
  the [run contract](../container.md#versioned-probe-and-live-lab-inputs) and
  the [split-host contract](../../container/agent/egress/README.md#split-agentservices-hosts).

  1.1.6).

## Fixed

- **Two inputs to one agent no longer merge into one message** (#2124).
  `oats session input` to a tmux home is serialized per home: each input
  holds the home's input lock from its paste to the end of its Enter's
  observation, so two inputs sent at the same moment are two messages, each
  with its own Enter. Before, the second paste could land ahead of the first
  Enter, the agent got both texts run together, and both callers read
  `verified: true`; a scheduled wake delivers through the same path. An input
  that waits more than 8 seconds for another is refused
  `E_SESSION_INPUT_FAILED`, nothing sent. A lock whose holder died is taken
  over, and text that holder pasted and never submitted is submitted on its
  own before the next input's text. The lock covers the kernel's inputs
  only: not keys typed in an attached terminal, nor a session provider's
  home ([Input](../desktop-cli-api.md#input)). The lock lives under
  `~/.oats`: a caller that may not write there (inside a sandbox) is
  refused `E_SESSION_INPUT_FAILED`, nothing sent.

- **An input no longer answers a permission prompt** (#2125). On a tmux home
  whose session holds a `permission` claim, a client's or a message's
  `oats session input` is refused with `E_SESSION_PROMPT_OPEN` and types
  nothing, as on a session provider. Before, its Enter chose the prompt's
  first option, so the command ran, the text was lost, and the answer said
  `verified: true`. The person answers the prompt in the agent's terminal
  (`oats session attach`) or through their client's prompt card; there is no
  override. A claim that outlived its dialog (Claude Code leaves it when a
  prompt is refused) refuses the same way until the session's next prompt
  or `oats instance waiting clear`; the refusal prints that command. Feature `session-input-permission-refusal` in
  `oats version --json` tells this refusal from a lost input. An input still
  answers other dialogs: a `question` claim's (AskUserQuestion takes the
  text; pi's confirm takes the Enter as its default option) and a startup
  dialog that raises no claim (Claude's folder trust)
  ([Input](../desktop-cli-api.md#input)).

- **Under session delivery, an idle agent is no longer published as
  degraded** (oats.aweb 1.49.2, awebai/oats-aweb#332). The host wake broker
  records its inspection of a session only at startup and before a delivery,
  so an idle home's recorded inspection aged into `degraded`
  (`oats.receive_unproven`) without any fault. Readiness now gives that age
  its own warning, `receive-inspection-aged`, which the status publisher does
  not count against a home its own inspection found alive. A stale broker
  snapshot (`receive-observation-aged`) and every broken precondition still
  read with their own reason.

- Desktop file viewing and brain skill metadata use bounded descriptor reads with path and
  file identity checks. In-root file links remain readable, and file replies report the number
  of bytes read.

- Desktop enables the renderer sandbox and bundles its terminal and workspace
  bridge. The Linux AppImage uses the OS sandbox where the system permits
  unprivileged user namespaces. ([Security posture](../desktop.md#security-posture))

- **A missing SQLite module names the fix.** When the turn record cannot
  load `node:sqlite`, it reports the Node version it needs and the version
  running, keeping the original error as its cause.
